# 模型预测

## 一、文章核心内容梳理

参考文章：[【华泰固收】构建利率走势的AI预测模型 —— 固收量化系列报告](https://mp.weixin.qq.com/s/1JjKk0AjQ9RpCC_awB0k7A)

这篇文章的核心不是去预测某个利率点位本身，而是把复杂的利率走势问题转化为更适合机器学习的“方向/状态分类”问题。其主要思想如下：

1. 预测目标应从“点位预测”转向“方向预测”
   - 对固收研究而言，方向通常比精确点位更重要。
   - 文章建议将未来利率变化划分为几类，例如“偏多、震荡、偏空”。
   - 这样做能降低任务难度，也更贴近投资决策。

2. 输入特征要尽量构造“真实世界”
   - 特征不应只包含单一市场变量，而应覆盖多个维度。
   - 文章将特征分为五大类：宏观经济、货币政策与流动性、债市供求、情绪与相对价值、高频基本面。
   - 本质上是让模型看到更完整的市场状态。

3. 数据处理比模型结构更重要
   - 必须先解决时间对齐、不同频率合并、未来信息泄露、异常值、缺失值等问题。
   - 文中强调低频数据要按“发布日期”而不是“统计期”合并。
   - 数值数据按频率做滚动鲁棒标准化，分类变量做独热编码。

4. 时序建模应使用“过去一段时间窗口”预测“未来一段时间结果”
   - 文章示例是：用过去 60 日市场环境，预测未来 5 日 10 年期国债收益率变化状态。
   - 这类任务天然适合 RNN、GRU、LSTM、TCN、Transformer 等序列模型。

5. 模型需要兼顾效果、可解释性和可维护性
   - 文章采用了 BiGRU-Inception-Attention 混合结构。
   - 但对当前项目来说，没有必要第一步就上复杂结构。
   - 更合理的顺序是：先做基线模型，再做深度学习升级。

6. 评估重点应放在“分类正确率、方向胜率、类别概率稳定性”
   - 固收研究使用模型的方式更接近“辅助判断”，而不是“自动交易”。
   - 因此比起单一数值误差，更应关注分类胜率、混淆矩阵、关键转向期表现。

## 三、建议的预测目标定义

结合文章思路和当前项目的数据形态，建议优先做“分类任务”，暂不直接做收益率点位回归。

### 方案 A：预测 10 年国债收益率未来 5 个交易日的变化方向

定义：

- 先计算未来 5 日收益率变化：

```text
y_future_5d = yield_t+5 - yield_t
```

- 再离散化为三分类：

```text
类别 0：y_future_5d <= -5BP    -> 偏多
类别 1：-5BP < y_future_5d < 5BP -> 震荡
类别 2：y_future_5d >= 5BP     -> 偏空
```

优点：

- 与文章思路一致；
- 易于评估；
- 更符合投资判断习惯。

### 方案 B：预测未来 1 周方向

如果你的最终特征是日频，可以继续用日频样本，但标签改成未来 5 个交易日或未来 1 周的方向标签。

### 方案 C：回归任务作为辅助

可以额外做一个回归模型预测：

```text
未来 5 日收益率变化幅度
```

但建议作为辅助任务，而不是第一优先级。

## 四、模型预测需要做的步骤

下面给出建议的完整实施路径，按“先简单、后复杂”的顺序推进。

### 步骤 1：确定目标变量

需要单独准备一列目标利率序列，例如：

- 中国 10 年期国债到期收益率
- 或者 10 年国债活跃券收益率

然后基于该序列构造标签：

```text
label_t = f(yield_t+5 - yield_t)
```

注意：

- 标签必须由“未来数据”生成；
- 但特征只能使用 `t` 时点及以前的数据；
- 这一步是整个监督学习任务能否成立的关键。

### 步骤 2：整合特征矩阵

以当前项目产出的 `data/43_data.csv` 和 `data/43_rate.csv` 为基础：

1. 读取 `43_data.csv`
2. 读取 `43_rate.csv`
3. 按日期将两者合并
4. 再把目标利率序列按日期合并进去

最终形成：

- `date`
- 多维特征 `X`
- 目标标签 `Y`

### 步骤 3：清洗并筛选可用字段

这里建议做一次建模前字段检查：

1. 删除纯空列、常数列、重复列
2. 检查高缺失率列
3. 检查是否存在明显的未来信息列
4. 确认所有特征在 `t` 时点都真实可见

建议额外输出一份字段清单，标记：

- 保留字段
- 删除字段
- 删除原因

### 步骤 4：构造时间窗口样本

文章的典型做法是：

- 用过去 60 日数据预测未来 5 日结果

具体可以构造：

```text
X_t = [t-59, t-58, ..., t] 的全部特征序列
Y_t = t 之后 5 日的收益率方向标签
```

最终样本张量维度通常为：

```text
[样本数, 时间步长, 特征数]
```

例如：

```text
[N, 60, F]
```

这一步是从“表格数据”切换到“时序样本”的核心步骤。

### 步骤 5：按时间切分训练集、验证集、测试集

不能随机切分，必须按时间顺序切分。

建议：

- 训练集：最早的 70%
- 验证集：中间的 15%
- 测试集：最后的 15%

或者采用滚动窗口验证：

1. 用早期区间训练
2. 用下一段时间验证
3. 再向前滚动

这样更符合真实交易场景。

### 步骤 6：先做基线模型

在深度学习前，建议先做两个基线模型，验证任务本身是否有可预测性。

#### 基线 1：XGBoost / LightGBM

输入方式：

- 不直接输入 60 日序列，
- 而是先把窗口内序列做统计特征提取，例如：
  - 近 5 日均值
  - 近 20 日波动率
  - 近 60 日最大最小值
  - 最近值与窗口均值之差

作用：

- 快速验证特征有效性；
- 可得到特征重要性；
- 训练成本低。

#### 基线 2：逻辑回归 / 线性分类器

作用：

- 检查问题是否存在最基本的线性可分性；
- 作为最弱基准线。

如果连基线模型都没有稳定超额表现，说明要先回头检查标签设计和特征质量。

### 步骤 7：构建时序深度学习模型

在基线有效后，再进入序列模型。

建议顺序：

1. GRU
2. BiGRU
3. BiGRU + Attention
4. TCN / Transformer 变体

推荐第一个正式版本使用：

```text
输入层 -> BiGRU -> Attention -> 全连接层 -> Softmax
```

原因：

- 结构足够强；
- 比完整的 BiGRU-Inception-Attention 更容易先跑通；
- 更适合当前项目从 0 到 1 落地。

### 步骤 8：处理类别不平衡

债券市场通常“震荡”样本最多，“大幅上行/下行”样本较少。

因此需要处理类别不平衡问题：

1. 统计三类样本占比
2. 对损失函数加 class weight
3. 或者对少数类做过采样

否则模型可能会倾向于一直预测“震荡”。

### 步骤 9：训练配置

建议最初采用如下配置：

- 损失函数：交叉熵损失
- 优化器：Adam
- 指标：Accuracy、Macro F1、各类别召回率
- 早停：Early Stopping
- 学习率衰减：ReduceLROnPlateau
- 批量大小：32 或 64

同时要固定随机种子，保证实验可复现。

### 步骤 10：评估模型

不能只看一个准确率，要至少看以下指标：

1. 总体准确率
2. Macro F1
3. 三分类混淆矩阵
4. 各类别 precision / recall
5. 转向期表现
6. 样本外稳定性

对固收研究尤其重要的是：

- 模型是否能识别“趋势切换”
- 模型给出的概率是否有区分度

建议输出：

- `P(偏多)`
- `P(震荡)`
- `P(偏空)`

而不是只输出最终类别。

### 步骤 11：做结果解释

即使使用深度学习，也建议补充解释模块：

1. 基线树模型特征重要性
2. SHAP 分析
3. 关键时点输入特征变化
4. 模型转向前后最敏感变量

这样更便于研究使用，而不是把模型当黑箱。

### 步骤 12：建立滚动更新机制

文章中提到模型需要定期更新，这一点非常重要。

建议：

- 每月增量评估一次
- 每季度或每半年重训一次
- 遇重大制度变化、疫情、地产周期切换等事件时额外重训

时间序列模型如果长期不更新，容易失效。

## 五、针对当前项目的推荐落地顺序

为了让模型能尽快从“预处理”走到“可预测”，建议按下面顺序推进：

### 第 1 阶段：先跑通监督学习样本

要做的事：

1. 准备目标利率日序列
2. 将 `43_data.csv`、`43_rate.csv`、目标利率表按日期合并
3. 构造未来 5 日标签
4. 生成过去 60 日窗口样本

阶段产出：

- `model_dataset.csv` 或 `model_dataset.parquet`
- `X_seq.npy`
- `y.npy`

### 第 2 阶段：验证任务是否可预测

要做的事：

1. 用逻辑回归做最小基线
2. 用 LightGBM / XGBoost 做强基线
3. 观察样本外准确率、F1、混淆矩阵

阶段目标：

- 确认标签是否合理
- 确认特征是否有效

### 第 3 阶段：正式训练时序模型

要做的事：

1. 上 GRU / BiGRU
2. 再加 Attention
3. 调整窗口长度、隐藏层维度、dropout、学习率

阶段目标：

- 看是否显著超过树模型基线

### 第 4 阶段：形成研究输出

要做的事：

1. 输出每日三类概率
2. 输出模型信号和实际结果对比
3. 标注关键转向时点
4. 形成研究结论和使用规则

最终可交付结果：

- 每日模型信号
- 概率分布
- 回测统计
- 关键因子解释

## 六、建议的文件与代码结构

建议后续新增如下模块：

```text
model/
  build_dataset.py        # 合并标签与特征，构造监督学习样本
  make_sequence.py        # 生成 [N, T, F] 时序样本
  train_baseline.py       # 训练逻辑回归 / LightGBM / XGBoost
  train_gru.py            # 训练 GRU / BiGRU 模型
  evaluate.py             # 输出准确率、F1、混淆矩阵、概率
  infer.py                # 用最新数据生成预测信号
```

如果暂时不想拆太多文件，最少也建议先做两个脚本：

1. `build_dataset.py`
2. `train_baseline.py`

这样可以最快验证建模方向是否成立。

## 八、结论

这篇文章对当前项目最有价值的启发有三点：

1. 预测任务要从“点位”转成“方向/状态分类”
2. 低频宏观数据必须按发布日期对齐，严格避免未来信息泄露
3. 先验证任务与数据，再逐步升级到更复杂的深度学习架构

结合当前项目现状，最合理的路线不是立即复刻文章中的大模型结构，而是：

```text
预处理结果 -> 构造标签 -> 构造时序样本 -> 基线模型 -> BiGRU/Attention 升级
```

这条路径更稳、更容易排查问题，也更适合当前工程继续推进。
